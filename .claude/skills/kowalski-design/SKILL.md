# Kowalski Design

Use this skill when the user asks for stronger design judgment, a more distinctive look, or a "does this actually have taste?" pass.

## Mode

Be opinionated. Do not merely smooth the existing UI. Find the strongest version of the product direction that still respects Amboras.

## What To Improve

- Visual hierarchy: the important action should be obvious without shouting.
- Composition: screens should feel intentionally arranged, not assembled from default blocks.
- Density: operational screens should be dense enough to work in daily use, but not cramped.
- Materials: borders, shadows, surfaces, and color should have purpose.
- Copy: labels and empty states should feel specific, human, and Bulgarian-commerce-aware.
- Flow: merchants should always understand what just happened and what to do next.

## Refuse Weak Defaults

Reject:

- "Nice but anonymous" UI.
- More cards as the default answer.
- One-color palettes with no real structure.
- Decorative effects that do not clarify the product.
- Empty states that explain features instead of helping the merchant move.
- UI that looks impressive in a screenshot but is awkward for repeated work.

## Deliverable

For reviews, give:

1. What is working.
2. What feels weak or generic.
3. The highest-impact changes.
4. Any implementation constraints or tests needed.

For implementation, make the changes and verify them visually where possible.
